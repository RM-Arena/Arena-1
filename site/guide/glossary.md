# 术语速查

看比赛时遇到生词，可以先在这里查一句话解释，再按链接深入。以下用法均指 Arena-1，赛季差异单独标出。

## 比赛与机器人

| 术语 | 通俗解释 |
| --- | --- |
| RoboMaster / RMUC | 机甲大师机器人赛事 / 其中的超级对抗赛。Arena-1 以其为基础做仿真适配 |
| 兵种 | 机器人在规则中的分工，如步兵、重型、哨兵。兵种影响能做什么 |
| 位置 / 编号 / slot | 队内身份，如 2027 的 1、3、4、6、7。不是型号编号 |
| 型号 / model | 具体硬件设计，如 2711 重型、2731 轮足步兵。同一兵种可以有多种型号 |
| 底盘 | 负责运动和承载的部分；麦轮、舵轮、轮足等设计有不同运动与越障能力 |
| 云台 | 调整发射机构朝向的部分。车体向前移动时，云台可以瞄向别处 |
| 装甲板 | 用于判定命中的部件。打到车壳或地面不等于有效命中 |
| 17mm / 42mm | 两种弹丸口径。前者常见于步兵，后者用于英雄或装炮后的重型 |
| 血量 / HP | 生命值。地面机器人血量耗尽后阵亡；基地被击毁会提前结束比赛 |
| 热量 | 发射机构的射击限制。开火增加热量、停火逐渐冷却；超限会锁定射击 |
| 超级电容 | 为底盘提供短时功率支持的储能部件；不能无限维持高速与爬坡 |

## 场地与资源

| 术语 | 通俗解释 |
| --- | --- |
| 基地 | 每队要保护的核心建筑，不是可移动的机器人 |
| 前哨站 | 带装甲的建筑，牵涉基地保护和区域争夺；2027 中还能变更归属与重建 |
| 增益卡 / 占卡 | 场地上可激活的区域 / 让符合条件的机器人停留在区域上。不是策略库里的策略卡 |
| 控制点（2027） | 由若干增益卡关联起来的区域目标。共有双方前哨、双方基地四个控制点 |
| 临时 / 完全控制（2027） | 控制点的两种状态，会影响基地保护和前哨重建，不等于“当前是否有人站着” |
| 控制度（2027） | 同时控制两方同类控制点时累计的数值，到时判胜首先比较它 |
| 堡垒 | 基地前方的战术区域，涉及防守增益、敌方基地装甲开启与控制点争夺 |
| 补给区 | 回血、补弹和复活相关区域。对方不能进入己方补给区 |
| 金币 / 经济 | 全队共享资源，用于弹药、立即复活和远程回血等；不是现实货币 |
| 能量单元 / 资源岛 | 科技装配所需的实体物件 / 取件地点 |
| 科技核心装配 | 用机械臂对准并操作核心，提升队伍等级上限、收入或防御；2027 由重型执行 |
| 能量机关 | 中央的旋转射击目标。按顺序打中发亮的目标可以为队伍获得增益，与搬运装配不同 |
| 机库（2027） | 6 号空中机器人系统的起降与维护设施。一套机库带若干架飞行器 |
| 虚弱 | 一种复活后的受限状态，通常需要回补给区域解除；不能当成满状态机器人使用 |

有关控制点的完整例子见[2027 规则图解](./rules-2027)。

## 策略开发与界面

| 术语 | 通俗解释 |
| --- | --- |
| Agent | 开发策略的 AI 助手；它在开发阶段写代码，比赛中运行的是写好的程序 |
| 策略 / policy | 接收观察并输出动作的 Python 程序 |
| 观察 / observation | 策略这一轮能知道的信息，含视野内目标与裁判公开数据；并非观战者的全场视图 |
| 动作 / actions | 策略给机器人的指令，如移动、瞄准、射击、机构操作和队内消息 |
| 状态 / state | 策略带到下一轮的 JSON 数据，可用来记住路线阶段、目标和历史信息 |
| 10 Hz | 每秒决策 10 次，即每 0.1 秒调用一次策略 |
| 工作区 | 一次开发任务的目录，包含代码、规则、SDK、练习客户端与计时信息 |
| SDK | 可供策略调用的辅助库，提供动作、瞄准、导航和几何工具 |
| 提交 / 版本 | 把当时代码保存成可参赛的固定版本；只改工作区文件不会自动更新已提交版本 |
| showcase.json / 战术卡 | 策略的图文展示数据，用于说明风格、路线、比赛阶段与决策，不是代码本身 |
| 策略卡 / 卡组 | 自由对战中可选的一份型号策略 / 保存好的出战组合 |
| 随机种子 / seed | 控制随机过程的输入，用于对照实验；数值重演仍需匹配规则与引擎 |
| 回放 / 录像 | 回放保存比赛数据，可以换视角查看；录像是导出的视频画面 |
| Elo | 根据有效对局结果更新的策略版本评分，不是单局伤害分，也不是通用能力保证 |
| GLB 外观 | 机器人三维模型文件，替换外观不会改变硬件性能 |
