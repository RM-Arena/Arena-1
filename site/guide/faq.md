# 常见问题

## 我没看过 RoboMaster，也不会写代码，能用吗？

可以。先读[从零认识比赛](./what-is-arena)，再按[第一场比赛](./getting-started)使用内置策略观战。你不需要组装机器人；熟悉兵种、基地和控制点后，再决定是否自己开发策略。

## 它是手动操作机器人，还是 AI 在实时聊天决策？

上场的是 Python 策略程序。人或 Agent 在开发阶段写代码，比赛时程序每 0.1 秒根据观察输出动作，不会逐帧调用语言模型。鼠标点击机器人主要用于选择、跟随与查看，不是手动驾驶。

## 当前默认是哪一季？为什么有时是 5v5，有时是 6v6？

默认规则是 RMUC 2027，RM 对战每方五个位置；2026 每方六个位置。应用可以记住地图选择，训练页也有赛季选择。自由对战的数量则取决于卡组。见[两季对照](./seasons)。

## 2027 是五台，为什么天上有那么多飞行器？

5v5 指五个出战位置。6 号是一套“机库 + 空中机器人”的系统，可以带 2–4 架飞行器；它们合起来仍是一套系统，每队最多一套。

## 为什么伤害领先还是输了？

2027 时间到首先比较控制度，然后才比较攻击伤害和存活地面机器人血量。2026 则先比较基地血量，再按前哨状态等条件比较。中途击毁基地也会提前结束；不能把计分板的攻击伤害当作唯一胜负分。见[2027 控制度](./rules-2027#控制度怎样增加)。

## 为什么打基地不掉血？

先看基地无敌条件：2027 中，对方完全控制其自己的前哨控制点时，基地不受伤害。还要区分装甲是否暴露、弹丸是否实际命中和发射机构是否有效。2026 的保护条件不同，是己方前哨站存活时基地无敌。

## 机器人到了圈里，为什么没有占下来？

先确认那是可激活的增益卡，机器人没有虚弱且满足兵种和时间条件；再看对方是否同时激活关联卡片、是否保持了所需时间。2027 的两个中央高地卡还有互斥条件。控制点由两处卡片关联，不能只看一个圆圈的颜色。

## 重型为什么一直搬东西，不开炮？

2027 重型开局没有发射机构。它需要达到 3 级装配或时间规则解锁条件，之后到工作台安装模块化 42mm，并完成首发确认。搬运和装配还为队伍提供科技收益。流程见[重型图解](./rules-2027#_4-重型-从搬运到火力)。

## 我换了阵容，为什么开始按钮不能用？

先检查红蓝策略是否为同一赛季，以及型号是否合规。全队策略各自绑定开发时的阵容，红蓝可以是不同型号，不必强凑同一套；没有锁定阵容的提交才使用选择器里的阵容。自由对战还要检查卡片是否可用、2027 是否重复部署机库。

## 同一个型号能在两个赛季使用吗？

部分步兵可以，但不是所有型号都可以，界面会显示合规结果。硬件跨季合规也不表示策略提交能跨季使用；目标赛季的任务、规则、机构和判胜都应重新核对。

## 训练的 90 分钟与比赛的 7 分钟是一回事吗？

不是。开发时间是创建任务时设置的连续窗口，包含阅读、编码、练习和提交；一局比赛通常是 420 秒。网页创建后自动启动开发计时；CLI 的 `new-agent` 和 `start-training` 是两个步骤。

## `arena.py results` 为什么提示缺参数？

它需要练习返回的任务 ID：`python -B arena.py results <练习任务ID>`。下载对应回放用 `python -B arena.py replay <练习任务ID> --game 0`。完整流程见[策略开发](./strategies)。

## 策略保存了，为什么策略库没更新？

在工作区保存文件只修改开发中的代码。先写好合格的 `showcase.json`，再在截止前执行 `python -B arena.py submit`，确认成功返回版本；修改代码后还要再次提交。训练结束后不会自动把未提交的编辑当成参赛版本。

## 必须用浏览器或安装 Python 吗？

桌面版包含独立窗口和运行比赛的 Python 环境。只运行已有策略不需要开发工具。外部编辑器或 Agent 调用工作区练习客户端时，需要可用的 Python 3，可以使用自己的解释器，或显式指定应用包中的解释器。

## 需要 Docker 吗？

内置示例和可信策略的本地体验无需 Docker。执行不可信策略使用 Docker 隔离模式，Docker 与对应镜像需要单独准备；隔离失败不会自动转成本地运行。见[执行模式](./getting-started#策略执行模式)。

## 随机种子相同，就一定能得到完全相同的结果吗？

种子适合控制随机条件，做实验时还应保持对手、阵容、策略版本、规则和引擎构建一致。仅有相同种子不足以保证不同平台或构建逐字节一致；数值重演校验需要匹配记录时的环境。

## 更新后旧回放还能打开吗？

桌面包保留历史资产与 v2 引擎用于兼容；但播放与数值重演是两件事，不能保证所有旧回放均能通过当前引擎的数值校验。当前地图选择也不会把 2026 回放转换成 2027。

## 自定义模型能增加性能吗？

上传 GLB 只替换外观，不增加血量、速度或火力，也不改变原型号的物理与合规判定。要比较性能，选择不同的合法硬件型号，并为相应阵容准备策略。

## 桌面版画质与浏览器版不同吗？

两者使用相同前端与素材，不以降低模型、阴影或像素比来封装桌面版。实际帧率和显示仍受显卡、驱动与系统缩放影响；模型资产和历史场景并不意味着任意硬件都有相同帧率。

## macOS 提示 Arena-1“已损坏，无法打开”怎么办？ {#macos-damaged}

v0.5.0 的 macOS 发布包跳过了应用签名，遗留的 Electron 签名无法通过完整性校验，
浏览器下载后会触发系统拦截。这种情况不代表 DMG 下载文件本身损坏。
当前源码已改用 ad-hoc 签名并增加 CI 签名校验，但仍未经过 Apple 公证；
修正需要重新构建发布才会反映到 GitHub 安装包中。

仅在确认安装包来自本项目 [GitHub Releases](https://github.com/RM-Arena/Arena-1/releases)、
并核对发布的 SHA256 后，才按以下方式处理。先将应用拖入“应用程序”目录，退出 Arena-1，
再打开“终端”。旧版签名损坏时先重新生成本地签名：

```sh
codesign --force --deep --sign - "/Applications/Arena-1.app"
codesign --verify --deep --strict --verbose=2 "/Applications/Arena-1.app"
```

校验成功后，如果仍被下载隔离拦截，可仅移除这个应用的下载隔离标记并打开：

```sh
xattr -rd com.apple.quarantine "/Applications/Arena-1.app"
open "/Applications/Arena-1.app"
```

这只处理 Arena-1，不需要全局关闭 Gatekeeper。ad-hoc 签名仅用于本地完整性校验，
不能证明发布者身份；如果重新签名失败或下载校验不符，应重新下载安装包。

## Ubuntu 出现 chrome-sandbox 错误怎么办？

优先使用 DEB 包。安装器配置 Electron 沙箱辅助程序与适用的 AppArmor 规则；AppImage 是否能启动取决于发行版的用户命名空间策略，不需要全局关闭 AppArmor 或使用 `--no-sandbox`。

## 文档网站能直接运行比赛吗？

不能。网站提供说明、图解与录像。比赛和训练运行在桌面应用或你启动的本机服务中，策略与练习记录保存在本地数据目录。
