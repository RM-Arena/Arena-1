# 局域网联机：8 名操作手、1 名主机裁判与观众

Arena-1 的局域网模式仍然由**一台主机运行仿真**：主机是权威裁判与计分方，其他设备只接收快照、发送驾驶输入。因此不需要两端同步物理，局域网延迟只影响操作手感，不会让比赛状态分叉。

一个房间包含三种角色：

| 角色 | 数量 | 能做什么 |
| --- | --- | --- |
| 主机裁判 | 1 | 选择赛季与双方策略、开始/暂停/结束、调速度、跳过赛前、黄牌/红牌/判负 |
| 操作手 | 8（RMUC 2027） | 凭 6 位 PIN 各占一台**地面机器人**，以第一视角驾驶；空中机器人由自动飞行系统控制 |
| 观众 | 不限 | 打开地址即观战；不占操作手席位，不能操作比赛 |

RMUC 2027 每方有重型、两台步兵、哨兵共 4 台地面机器人，因此双方合计正好 8 个操作手席位。切到 RMUC 2026 时会变成 10 个席位（每方多一台工程机器人），空中机器人始终不可驾驶。

## 1. 启动

### 浏览器 / 源码

```bash
python scripts/project.py run --lan
# 或者
python -m rmuc_arena serve --lan --port 8765
```

启动日志会打印类似下面的地址与 PIN：

```
Arena-1 LAN lobby: http://192.168.0.3:8765, http://127.0.0.1:8765  PIN: 246810
```

主机自己打开 `http://127.0.0.1:8765`，其他电脑/平板打开日志里的局域网地址。

### 桌面版

菜单「执行模式 → 局域网联机 / LAN lobby」切换后会自动重启后端；打开「联机」页即可看到地址与 PIN。

> 只在本机观战/开发时不加 `--lan`，服务仍然只监听 `127.0.0.1`，不会暴露到局域网。

## 2. 加入

1. 主机进入「联机」页，确认地址与 PIN。
2. 操作手在另一台设备打开该地址，进入「联机」→ 输入名字与 PIN →「以操作手加入」。
3. 在红/蓝方席位中点「选择」占一台地面机器人，点「准备」。
4. 主机选择赛季、双方策略与时长后点「开始比赛」。
5. 所有人点「进入战场」。操作手进入倒计时结束后会自动坐进自己的机体；观众看到的是同一场比赛。

席位是独占的：同一台机体被占用时其他操作手会得到提示；主机裁判可以「收回」离线或误占的席位。操作手退出驾驶或断线 30 秒后会释放席位。

## 3. 网络与安全

- **PIN**：只有操作手需要 PIN；观众直接观战。PIN 每次启动重新生成，只在主机页显示。
- **写操作只属于主机**：开始/暂停/结束、策略上传、模型上传、战场设置、删除记录等非回环请求都会返回 403；操作手只能驾驶自己的席位。
- **Host 白名单**：只接受本机地址、机器名与启动时探测到的局域网 IP，防止恶意网页通过 DNS rebinding 访问本机服务。
- **不计 Elo**：只要服务以局域网模式运行，比赛就标记为 `test_match`，人类驾驶不会污染策略排行榜。
- 桌面的「可信本地策略」模式会以主机用户权限执行上传的策略；开放局域网时建议同时使用 Docker 隔离（菜单「执行模式 → Docker 隔离」），并且只把 PIN 发给可信玩家。

## 4. 延迟与带宽

- 驾驶输入走已有的 WebSocket，20 Hz 发送；服务端收到后立即写入该机体的手动指令，下一次物理步进生效，局域网下典型延迟为「网络往返 + 一个 50 ms 步进」。
- 每名观众约 1.8 Mbit/s（permessage-deflate 压缩后），10 名观众约 18 Mbit/s；建议使用有线或 5 GHz Wi-Fi，并关闭路由器的 AP 隔离/访客网络隔离。
- Windows 首次监听 `0.0.0.0` 会弹出防火墙提示，请允许「专用网络」。端口被占用时可换 `--port 8800`。

## 5. 限制

- 一个服务进程同时只运行一场比赛；需要多场并行时，用不同端口/不同数据目录启动多个实例。
- 不支持 P2P/双端仿真，也不支持不同机器各跑一份策略；策略仍在主机侧执行。远程作者可以通过带 PIN 的主机页面提交策略，由主机在房间里选择。
- 空中机器人不提供驾驶席位；回放中不能接管。
